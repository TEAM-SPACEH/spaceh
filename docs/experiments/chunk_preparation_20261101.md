# 청킹 비교 실험 준비 결과

2026-11-01, **로컬 사전 검사 완료·새 비교의 API 평가는 미실행**.
이 문서는 준비 시점의 기록이다. 이후 승인받아 실행한 [1차 결과](chunk_size_results_20261101.md)는 별도로 확인한다.

## 질문과 원본

- [전체 질문·정답](chunk_questions_development.md): 비교용 30개 + 추출 오류 진단용 4개.
- 새로 추가한 22문항은 원본 PDF·DOCX에서 확인했고, 지정 위치의 고정 추출 결과에서도 발췌가 모두 확인됐다.
- 원본 4개를 한 번 추출·마스킹해 고정했다. 블록 수는 사업보고서 3,799개, 카탈로그 950개, ARIA 11개, 중동 보고서 65개다.
- 모든 설정이 이 블록을 공유한다. 재실행에서는 같은 입력의 고정 블록을 재사용하는 것도 확인했다.
- BASE와 기존 앱 청크는 개수가 1,736개로 같지만, 카탈로그 23개 청크의 본문이 달랐다. 새 추출에는 이미지 OCR 문자 등이 추가돼 있다. 메타데이터 차이는 없었다.
  따라서 과거 기준선 점수는 가져오지 않고 **새 고정 블록으로 만든 BASE를 다시 평가**한다. 기존 앱 색인은 수정하지 않았다.

## 실제 생성한 1차 후보

| 크기/오버랩 (글자) | 청크 수 | 전체 임베딩 입력 토큰 |
| --- | ---: | ---: |
| BASE: 800/150 | 1,736 | 525,373 |
| 400/40 | 2,416 | 644,490 |
| 800/80 | 1,728 | 519,733 |
| 1200/120 | 1,595 | 496,002 |
| 1600/160 | 1,536 | 482,823 |

청크 본문·출처를 `cl100k_base`로 센 값이다. **토큰 수가 적다고 검색 성능이 좋다는 뜻은 아니다.**
다섯 설정의 동일 입력을 중복 제거하면 3,243개 텍스트·1,211,281토큰이다.
이는 문서 청크 임베딩 입력량이며 질문 임베딩과 평가 모델의 입력·출력 토큰은 별도다. 금액은 산정하지 않았다.

## 준비한 실행 코드

- `scripts/compare_chunk_settings.py`: 기본 실행은 API 없는 추출·청킹·근거 발췌·토큰 검사다.
- 전송 옵션이 있을 때만 별도 실험 색인을 만들고 기존 검색 서비스로 벡터/하이브리드를 각각 실행한다.
- Top 10과 4,000토큰 조건을 분리하고, 문서별·본문/표/OCR별 요약과 수동 검토 목록을 남긴다.
- 2차는 사람이 1차 결과를 확인한 뒤 크기를 지정해 실행한다. 앱 설정을 자동 변경하지 않는다.
- 기존 기준선의 원본 JSON·결과와 앱 소스·DB·색인은 변경하지 않았다.

## 검증

추가 실험 도구·기존 평가기·청커·하이브리드·권한 테스트 **79개 통과**.
실험용 실제 Chroma 색인 생성·검색·경로 복원도 검사했다. 테스트의 외부 API는 모의 처리했다.
로컬 사전 검사에서 임베딩·평가 API 호출은 **0건**이었다.

실제 API를 통한 새 후보 색인·검색·정답 판정은 아직 검증하지 않았다.
별도 최종 확인용 질문 30개도 아직 없으며, 같은 원본 근거를 공유하는 개발 문항의 상관을 고려해야 한다.
