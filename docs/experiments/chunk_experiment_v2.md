# 청킹 크기·오버랩 비교 실험

이하 앱 기본값은 실험 당시의 800/150을 뜻한다. #136에서 요청한 현재 기본값 800/80 적용과 재색인 절차는 [자료 안내](README.md)를 따른다. 실험 BASE는 800/150으로 유지한다.

## 목적

문서를 얼마나 길게 나눠야 질문의 정답 근거를 잘 찾는지 비교한다.
청크는 검색에 사용하는 문서 조각이며, 겹침은 앞뒤 조각에 반복해서 넣는 글자 수다.
**하이브리드 검색을 주 기준으로 크기부터 고르고, 그 크기에서 오버랩을 조정한다.**
벡터 검색은 보조 확인용이며 하이브리드 점수와 합산하지 않는다.
2026-11-01 사용자가 1차 결과를 확인한 뒤 주 기준을 벡터에서 하이브리드로 변경했다.
결과 확인 후의 기준 변경이므로 사전 확정된 검증 실험이 아닌 탐색적 비교로 해석한다.
기존 10월 30일 실험은 설정 선택에 사용하지 않고 기록만 보존한다.

## 확정한 탐색 범위

크기는 현재 청커의 **글자 수** 기준이며 토큰 수가 아니다. 아래 값은 최적값이 아니라 탐색 후보다.
400~1,600자는 짧은 근거부터 긴 문맥까지 비교하기 위한 범위이고, 10%는 크기 탐색 중 겹침 비율을 맞추기 위한 출발점이다.

### 1차: 크기 선택

| 설정 | 청크 크기 | 오버랩 | 비율 |
| --- | ---: | ---: | ---: |
| S400 | 400자 | 40자 | 10% |
| S800 | 800자 | 80자 | 10% |
| S1200 | 1,200자 | 120자 | 10% |
| S1600 | 1,600자 | 160자 | 10% |
| BASE: 현재 기본값 | 800자 | 150자 | 18.75% |

S400~S1600 중 크기를 하나 고른다. BASE는 현재 설정과의 비교 기준으로 함께 평가한다.
BASE가 더 좋더라도 이를 숨기지 않고 최종 후보 비교에 남긴다.

### 2차: 오버랩 선택

1차에서 고른 크기를 N이라고 할 때 다음 세 설정을 비교한다.

| 설정 | 청크 크기 | 오버랩 |
| --- | ---: | ---: |
| O0 | N자 | 0자 (0%) |
| O10 | N자 | N ÷ 10자 (10%) |
| O20 | N자 | N ÷ 5자 (20%) |

예를 들어 N=800이면 오버랩은 0·80·160자다. O10은 1차와 같은 입력이면 결과를 재사용한다.
최종 후보는 BASE와 비교한다. 결과가 비슷하면 기본값을 유지하고 우위를 단정하지 않는다.
총 고유 설정은 최대 7개다. 모든 크기×오버랩 조합을 검사하지 않으므로 전역 최적값을 찾았다고 주장하지 않는다.

표는 기존 청커처럼 행 단위로 나누고 오버랩을 적용하지 않는다. 표 머리글과 문맥은 반복될 수 있다.
긴 단일 행은 설정 크기를 초과해도 보존하므로 실제 최대 길이도 기록한다. 본문과 표 결과는 따로 확인한다.

## 준비

- 공개 자료·모의 문서 중 본문, 표, 이미지 글자(OCR)가 포함된 PDF·DOCX·PPTX를 사용한다.
- 질문은 설정 선택용 30개와 최종 확인용 30개를 목표로 준비한다.
  같은 근거를 묻는 질문은 한쪽에만 넣고, 가능하면 문서도 나눈다.
- 검색 전에 질문별 정답과 원본의 근거 위치를 정한다. 숫자는 항목·단위·기간도 적는다.
- 기존 12문항은 설정 선택용으로만 재사용한다. 질문이 부족하면 실제 개수를 밝힌다.
- 현재 개발 문항은 비교용 30개와 추출 오류 확인용 4개다. 같은 페이지·표 문항이 많고 별도 최종 검증 세트는 아직 없으므로 일반적인 최적값을 확정하지 않는다.

## 진행 순서

1. 원본과 대조해 텍스트·표·OCR 추출을 확인한다. 마스킹한 블록을 한 번 고정하고 모든 설정에 동일하게 사용한다. 설정마다 OCR을 다시 돌리거나 내용을 보정하지 않는다.
2. 문서 목록, 메타데이터·출처, 임베딩 모델, 질문, 권한, 검색·평가 설정을 고정한다. 정답 문서만 골라 검색하지 않는다.
3. 기존 앱 색인·DB·기본값을 바꾸지 않고 별도 실험 색인을 만든다. BASE도 동일한 추출 블록으로 새로 만든다. 과거 색인의 점수는 직접 비교하지 않는다.
4. 1차 후보와 BASE를 평가해 크기를 고른다. 이후 2차 후보로 오버랩을 고른다. 두 단계에서 같은 설정 선택용 질문을 사용한다.
5. 각 설정의 검색 결과를 다음 두 조건으로 각각 평가한다.
   - **주 지표 — 하이브리드·같은 분량:** 상위 30개 중 순서대로 총 4,000토큰까지 확인한다.
     청크 본문과 출처를 포함하고 질문·평가 프롬프트는 제외한다. 토크나이저를 고정하고 기록한다.
     다음 청크가 한도를 넘으면 멈추며, 잘라 넣거나 건너뛰어 뒤 청크를 넣지 않는다. 빈 결과도 실패로 포함한다.
   - **보조 지표 — 앱 기준:** 하이브리드 검색 상위 10개를 확인한다.
   - 벡터도 같은 두 조건으로 평가하되 별도 표에 기록한다. 하이브리드와 벡터 점수를 합산하지 않는다.
6. 설정 선택용 질문으로 고른 후보를 새로운 최종 확인용 질문에서 BASE와 비교한다.
   최종 결과를 보고 설정을 다시 고르면 새로운 검증 질문이 필요하다. 이 실험만으로 앱 설정을 자동 변경하지 않는다.

## 평가 방법

**검색된 내용만으로 정답에 필요한 사실을 모두 확인할 수 있으면 성공이다.**
표현이 달라도 뜻이 맞으면 인정하며, 숫자는 항목·단위·기간까지 확인한다.
검색되지 않은 청크를 추가해서 성공으로 처리하지 않는다.

- 설정 이름을 가리고 OpenAI 모델이 필수 사실별로 판정한다. 실제 청크에 없는 인용은 코드로 걸러낸다.
  일부 문항과 애매한 결과는 사람이 원본·검색 근거와 대조한다. [실행 방법](llm_evaluation.md)
- 검토 필요 문항과 설정 간 통과·실패가 달라진 문항은 같은 기준으로 수동 확인한다. 자동 결과는 보존하고 수동 정정·이유를 따로 기록한다. 미해결 검토가 순위를 바꿀 수 있으면 후보 선택을 보류한다.
- OCR·표 추출 실패는 따로 표시하고, 추출이 정상인 질문의 결과도 함께 집계한다.
- 성공 문항 수와 함께 본문·표·OCR별 결과, 청크 수, 사용 토큰 수와 처리 시간을 기록한다.
- 후보는 **하이브리드 4,000토큰 기준의 성공 문항 수 → 하이브리드 Top 10의 성공 문항 수 → 전체 색인의 임베딩 입력 토큰이 적은 순서**로 고른다. 추출 오류 진단 문항은 이 순위의 분모에서 제외한다. 모호한 Q04도 모든 설정에서 동일하게 제외해 29문항으로 선택한다.
- 토큰 비용 비교에는 캐시로 절약된 실제 청구량이 아니라 각 설정의 전체 청크 입력 토큰 합계를 사용한다. 실제 API 사용량도 별도로 기록한다.
- 위 기준이 모두 같으면 작은 크기, 같은 크기에서는 적은 오버랩을 잠정 후보로 삼되 성능 우위는 주장하지 않는다.
- 최종 비교에서는 BASE만 성공한 질문과 후보만 성공한 질문을 공개한다.
  질문 수가 적거나 차이가 작으면 우위를 단정하지 않고, 유형별 실패와 비용도 확인한다.

검색 순위·청크 ID·근거 위치·판정 이유와 실행 코드·버전·설정·파일 해시를 남긴다.
원본과 청크 본문은 로컬 `data/`에 보관하고 Git에 올리지 않는다.
이 테스트는 **검색 근거를 찾는 성능**을 평가하며, AI 답변 정확도는 별도 평가한다.

- 원본 4개를 한 번 추출해 고정했고, 추가 22문항의 근거 발췌 검사를 통과했다. 실험 도구·청커·평가기·검색·권한 테스트 79개 통과. [준비 결과](chunk_preparation_20261101.md)
- 사용자 전송·비용 동의 후 **1차 크기 비교 680개 조합을 완료**했다. [결과·근거 대조·민감도](chunk_size_results_20261101.md). 기존 24건 기준선과 구분한다.
- Q04를 제외한 엄격한 근거 대조에서 400/40과 1600/160은 벡터 4,000토큰 22/29·Top 10 21/29로 같았다. 입력 토큰이 적은 1600/160을 잠정 후보로 골랐지만, Q23 대상 문맥 기준을 완화하면 400자가 앞선다. 최적값으로 확정하지 않는다.
- 위 벡터 선택은 당시 기준의 기록이다. 이후 사용자 요청으로 하이브리드 중심으로 변경했고, 300개 조합의 근거 대조에서 400/40·800/80이 4,000토큰과 Top 10 모두 26/29로 같았다. 전체 임베딩 입력이 적은 800/80을 잠정 선택했다.
- 사용자 승인으로 2차 **800자, 오버랩 0·80·160자**의 544개 조합을 완료했다. 하이브리드 근거 대조 후 800/80을 잠정 선택했다. [2차 결과·재검색 변동·사용량](chunk_overlap_results_20261101.md)
- 800/80은 2차에서 4,000토큰 27/29·Top 10 26/29였다. 1차 대비 1문항 증가는 같은 설정 재검색에서 후보가 달라진 결과이므로 오버랩 개선으로 해석하지 않는다. 별도 최종 검증은 아직 없고 앱 기본값은 800/150으로 유지한다.
- 결과를 확인한 뒤 기본 설정 변경 여부를 결정한다.
