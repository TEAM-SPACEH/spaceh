# 청크 크기·겹침 실험 — 2026-10-30

## 진행 방법

1. 무벡스 사업보고서·전망용 카탈로그·ARIA 모의 기획안·중동 모의 보고서, 총 4개 문서를 선정했다.
2. 기존 로더로 텍스트·표·이미지 OCR을 추출하고 개인정보를 마스킹했다. 이 결과를 한 번 고정해 모든 설정에서 재사용했다.
3. 400/75·800/150·1200/225(크기/겹침, 문자 단위)로 청킹했다. 같은 `text-embedding-3-small` 모델로 임베딩하고, 설정마다 별도 실험용 Chroma 컬렉션에 저장했다.
4. 정답과 근거 위치를 정한 동일한 12개 질문으로 벡터·하이브리드 검색을 실행했다. 질문 벡터·관리자 권한·검색 대상 4개 문서를 고정하고 상위 5개 결과를 평가했다.
5. 먼저 정답의 핵심 단어가 검색 결과에 있는지 확인해 1200자를 추가 실험 대상으로 골랐다. 이후 겹침 0자·300자도 비교했다. 아래 표는 모든 설정에 다음 평가 기준을 적용한 결과다.

## 평가 기준

**정답을 뒷받침하는 문구가 검색된 청크에 그대로 들어 있는지 확인했다.** 비교할 때는 공백·줄바꿈 같은 차이를 정리했다.

예를 들어 확인할 문구가 `냉난방 효율 향상`이라면 다음처럼 판단한다. 아래는 방법을 설명하기 위한 예시다.

| 검색된 내용 | 판단 |
|---|---|
| `냉난방 효율 향상`이 이어진 문구로 있음 | 근거 확인 |
| `냉난방`과 `향상`이 서로 다른 문장에 흩어져 있음 | 근거 미확인 |
| `냉난방 효율이 좋아진다`처럼 뜻은 같지만 표현이 다름 | 이 방식에서는 놓칠 수 있음 |

정답에 필요한 문구가 여러 개면 모두 찾아야 한 문항을 ‘근거 확인’으로 센다. 문구가 원문에서 이웃한 두 청크에 걸쳐 있으면, 검색된 두 청크를 이어서 확인했다.

**뜻을 이해해 정답을 판정한 것은 아니다.** 따라서 ‘미확인’은 반드시 오답이라는 뜻이 아니며, 표의 `9/12`는 12개 질문 중 9개에서 필요한 근거 문구를 찾았다는 뜻이다.

## 한계

- 같은 4개 문서·12문항으로 설정 선택과 평가를 진행한 예비 실험이다. 실제 답변 정답률·전체 44문서·새 질문 성능은 미검증이다.
- 실험은 상위 5개, 앱 기본은 상위 10개 검색이다. 크기별 검색 본문량·토큰 비용 차이는 통제하지 않았다.
- 추출된 블록을 기준으로 평가했으며 ARIA OCR의 원본 슬라이드 대조는 남아 있다.

기존 제품 코드·원본·기본 DB는 보존했다.
