# OpenAI로 검색 근거 평가하기

현재 저장된 청크를 검색해 질문 12개를 평가하는 코드다.
**청크 설정 비교를 실행하는 코드는 아니다.** 새 2단계 비교에는 [별도 실행 도구](chunk_comparison_run.md)를 사용한다.

## 판정 방법

1. 기존 검색 서비스로 벡터·하이브리드 검색을 각각 실행한다. 권한 필터를 검색 전에 적용한다.
2. 질문·정답·필수 사실과 검색된 상위 청크를 평가 모델에 보낸다.
3. 사실마다 `supported`(확인), `unsupported`(근거 없음), `contradicted`(모순), `uncertain`(애매함)을 받는다.
4. 인용 청크 ID·문서 ID와 인용문이 실제 검색 본문에 있는지 코드로 검증한다.
5. 필수 사실이 모두 확인돼야 성공이다. 가짜 인용·애매한 판정은 수동 확인 대상으로 남긴다.

표현·단위 환산 차이는 허용하지만 대상·행·열·단위가 맞아야 한다.
모델은 정답이나 외부 지식으로 근거를 보충하면 안 된다.
인용문 존재 검사는 의미가 맞는지까지 보장하지 않으므로 일부 결과는 사람이 대조한다.
오류 확인용 4문항은 비교용 8문항의 성공률에 합치지 않는다.

응답 형식은 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)의 JSON Schema를 사용한다.

## 실행

프로젝트 가상환경을 활성화한 뒤 저장소 루트에서 실행한다.

```bash
# 원본 해시·색인·청크 수만 검사한다. API 호출 없음.
python -X utf8 -m scripts.evaluate_retrieval

# 전송 범위를 확인하고 승인한 경우: 첫 문항의 하이브리드 검색·평가
python -X utf8 -m scripts.evaluate_retrieval --send-to-openai --method hybrid --limit 1

# 12문항 × 벡터·하이브리드, 총 24건 평가
python -X utf8 -m scripts.evaluate_retrieval --send-to-openai
```

- 키는 `.env`의 `OPENAI_API_KEY`, 모델은 `LLM_MODEL`을 사용한다.
- 전송 내용은 질문·정답·필수 사실·검색된 청크 본문과 출처 위치이며 목적지는 OpenAI API다.
- 질문 임베딩과 모델 평가에 API 비용이 발생한다. 같은 질문 벡터·동일 평가 입력은 캐시한다.
- 원본 문서를 다시 임베딩하거나 앱의 색인을 변경하지 않는다.
- 관리자 `ADM-0001`을 DB에서 확인하며, 검색 후보는 질문셋의 4개 문서 전체다.
  정답 문서만 미리 골라 검색하지 않는다.
- 실행 중 원본이나 색인이 바뀌면 결과를 무효로 표시한다.
- 검색 감사 로그는 이 실험에서 생략하고 로컬 결과 파일에 실행 정보를 남긴다.

## 결과 저장

`.venv/retrieval_eval/`에 다음 파일을 저장한다. Git에는 올리지 않는다.

- `preflight.json`: API를 호출하지 않은 사전 검사 결과
- `results.json`: 문항별 검색 청크·필수 사실별 판정·인용·검증 결과·토큰 사용량
- `query_embeddings.json`, `judge_cache/`: 재실행 비용을 줄이는 캐시
- `synthetic_cache/`: 실제 문서와 무관한 합성 예제의 API 연결 검사 결과

모델·프롬프트·질문·검색 내용이 달라지면 평가 캐시를 재사용하지 않는다.
API 오류는 검색 실패로 집계하지 않고 중단 사유로 남긴다.

## 현재 검증 범위

합성 데이터로 `gpt-4o-mini-2024-07-18`의 실제 API 응답과 인용 검증을 확인했다.
최초 실제 문서 호출은 전송 승인 범위 부족으로 차단됐으며, 이후 전송 내용을 설명하고 사용자에게 명시적인 동의를 받았다.
실제 업로드 문서의 12문항 × 검색 2종 = 24건 평가를 완료했다. [결과와 수동 검토](llm_baseline_20261101.md)를 참고한다.
평가기 단위 테스트 18개가 통과했다. 모델의 거짓 실패와 잘못된 인용도 발견했으므로 자동 판정을 최종 정답으로 취급하지 않는다.
