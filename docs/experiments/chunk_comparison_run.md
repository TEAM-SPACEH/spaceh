# 청킹 비교 실행 방법

기본값 유지에 관한 설명은 실험 당시의 원칙이다. 이후 #136의 앱 기본값 800/80 적용과 기존 문서 재색인 절차는 [자료 안내](README.md)를 따른다. 실험 BASE는 당시 비교 기준인 800/150으로 유지한다.

[현재 계획](chunk_experiment_v2.md)에 따라 **하이브리드 검색으로 크기·오버랩을 선택**한다.
1차 결과 확인 후 사용자 요청으로 주 기준을 변경했으므로 탐색적 비교다.
벡터 결과는 별도 참고용이다. 기존 앱 소스·DB·색인은 변경하지 않는다.

## 질문

- 기존 [12문항](chunk_questions_v2.md) + [추가 22문항](chunk_questions_additional.json).
- 합계: **비교용 30개, 추출 오류 진단용 4개**. 진단용은 선택 점수에서 제외한다.
- 한눈에 읽을 수 있는 [전체 질문·정답 목록](chunk_questions_development.md).
- 문서별 비교용: 사업보고서 10개, 카탈로그 10개, 중동 모의 보고서 9개, ARIA 1개.
- 추가 질문은 원본의 정답·위치를 확인하고, 고정 추출 블록에 원본 발췌가 남아 있는지도 검사한다.
  발췌 검사만으로 표의 행·열이나 문장의 의미까지 검증되지는 않는다.
- 같은 페이지·표에 여러 질문이 있어 30개의 독립 사례는 아니다. 결과는 문서별·본문/표별로도 확인한다.
- 이 34문항은 **설정 선택용**이다. 별도 최종 확인용 30문항은 아직 준비하지 않았다.

## 명령

가상환경을 활성화하고 저장소 루트에서 실행한다.

```bash
# 1. 원본 4개를 한 번 추출·마스킹해 고정하고 후보별 청크·토큰 수 계산.
#    임베딩·평가 API 호출 없음. 첫 실행은 로컬 OCR 때문에 시간이 걸린다.
python -X utf8 -m scripts.compare_chunk_settings

# 2. 전송 범위·비용을 확인하고 동의한 뒤에만 1차 실험 실행.
python -X utf8 -m scripts.compare_chunk_settings --send-to-openai

# 3. 1차 결과와 검토 목록을 사람이 확인한 후 크기를 결정.
#    하이브리드 결과 대조 후 선택한 크기는 800자다.
python -X utf8 -m scripts.compare_chunk_settings --stage overlap --selected-size 800
python -X utf8 -m scripts.compare_chunk_settings --stage overlap --selected-size 800 --send-to-openai
```

1차는 BASE(800/150)와 400/40·800/80·1200/120·1600/160이다.
2차는 BASE와 선택한 크기의 오버랩 0·10·20%다. 같은 입력은 캐시를 재사용한다.
단계 전환과 최종 선택은 자동으로 하지 않는다. 수동 검토 후 계획의 선택 기준을 적용한다.
중단 후 같은 명령을 실행하면 입력·모델·프롬프트를 확인하고 완료된 조합과 동일 실험 색인을 보존해 이어간다.
완료된 결과는 API를 다시 호출하지 않고 반환한다. 실행 코드 해시는 재개 시도별로 남긴다.

## 전송과 비용

`--send-to-openai`를 붙이면 고정 문서의 **청크 본문·출처와 질문을 임베딩 API**에 보낸다.
또한 질문·정답·필수 사실·검색된 청크를 평가 API에 보낸다. 키는 `.env`에서 읽고 출력하지 않는다.
기존 24건 기준선 평가와 달리 새 청크 전체의 임베딩이 필요하므로 전송량과 비용이 늘어난다.

1차 판정 조합은 최대 **5설정 × 34문항 × 2검색 × 2분량 = 680건**이다.
동일한 근거를 보내는 조합은 평가 캐시로 중복 요청을 줄인다. 사전 검사 파일의 토큰 수는 금액이 아니다.
캐시 전후 실제 사용량과 설정별 전체 청크 입력 토큰을 따로 기록한다.

## 결과 확인

`.venv/chunk_experiment/<입력 식별자>/`에 저장하며 Git에서 제외한다.

- `corpus.json`: 모든 설정이 공유하는 마스킹 완료 블록·메타데이터·원본 스냅샷.
- `preflight_size.json`, `preflight_overlap.json`: 청크 수·전체 입력 토큰·근거 발췌 점검.
- `indexes/<임베딩 모델 식별 해시>/<설정명>/`: 앱과 분리된 모델·설정별 실험 색인. 같은 모델·설정은 재사용하지만 다른 모델의 색인은 재사용하지 않는다. 기존 모델 구분 없는 색인은 삭제하지 않고 새 실행에서 사용하지 않는다. 이미 완료된 결과는 그대로 반환한다.
- `results_*.json`: 설정·검색·분량·문항별 근거·판정·인용·사용량·요약.

주 지표는 `tokens4000`의 `hybrid` → `chunking` 결과다. 모호한 Q04를 제외한 29문항을 근거 대조해 선택한다.
하이브리드 `top10`은 보조 선택 지표이고 `vector` 결과는 별도로 본다.
토큰 예산은 `cl100k_base`로 출처·청크 연결 줄바꿈까지 세며, 초과하는 다음 청크 앞에서 멈춘다.
Top 10 하이브리드는 실제 앱처럼 검색별 후보 30개를 결합하고, 4,000토큰 조건은 검색별 후보 90개를 결합해 상위 30개를 사용한다.
두 조건의 하이브리드 순위가 같다고 가정하지 않는다.

`manual_review_queue`에는 검토 필요·설정 간 결과 차이 문항을 남긴다.
완료 상태도 `complete_pending_manual_review`이므로 자동 점수를 최종 선택 결과로 읽으면 안 된다.
오류·원본/기존 색인 변경 시 성공률 비교에 사용하지 않는다. 실험 당시에는 새 질문으로 BASE와 최종 후보를 검증하기 전 앱 기본값을 유지하는 것을 원칙으로 했다. 이후 사용자 요청으로 기본값 800/80 적용을 진행했으며, 독립 최종 검증이 완료됐다는 뜻은 아니다. 현재 적용·재색인 절차는 [자료 안내](README.md)를 따른다.

## 검증

추가 실험 도구·기존 평가기·기존 청커 테스트를 함께 실행한다.
실험용 실제 Chroma 색인에서 검색하는 테스트도 포함하되, 외부 API는 모의 처리한다.
2026-11-01: 재개·중복 방지 검증과 기존 하이브리드·권한 테스트를 합쳐 **82개 통과**했다.
로컬 사전 검사에서 추가 22문항의 근거 발췌가 모두 확인됐다. [준비 결과](chunk_preparation_20261101.md)
이후 사용자 동의로 1차 680개 조합을 완료했다. [실제 결과와 해석 한계](chunk_size_results_20261101.md)
주 기준을 하이브리드로 변경한 뒤 800자·오버랩 0/80/160의 2차 544개 조합도 완료했다. [2차 결과·정정·재검색 변동](chunk_overlap_results_20261101.md)
2차 실행 때 동일 설정에서도 일부 검색 후보가 달라져 기존 결과가 전부 그대로 재사용되지는 않았다. 동일한 평가 입력만 캐시를 재사용한다.

```bash
python -X utf8 -m unittest tests.test_chunk_settings_experiment tests.test_retrieval_evaluation tests.ingestion.test_chunker
```

평가 프롬프트·인용 검증은 기존 평가기를 재사용한다.
모델 판정과 수동 대조를 함께 사용하는 원칙은 [OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고했다.
