# 구조 개요

## 1. 전체 흐름

```text
[적재]  원본 파일 / DART API
          │  parsers (I-01, I-04, I-05)
          ▼
        공통 문서 형식 (NormalizedDocument)
          │  masking (I-03) → chunker (I-02)
          ▼
        Chunk ──임베딩──▶ Chroma 컬렉션 "documents"      (검색 단위)
        문서 메타데이터 ──▶ MySQL documents               (관리·권한·공유)

[사용]  로그인 (M-01) → 세션에 현재 사용자 (역할·소속)
          │
          ▼
        S-03 권한 필터 생성 ──▶ 검색 (S-01·S-02·S-06) ──▶ 답변 (S-04) ──▶ 출처·원문 (S-05)
                            └─▶ 보고서 수집 (R-01) ──▶ 생성 (R-02) ──▶ 각주 (R-03) ──▶ 요약·내보내기 (R-04·R-05·A-06)

[기록]  모든 행위 ──▶ 감사 로그 (A-04) ──▶ 관리자 조회 / 내 히스토리 (M-04)
```

적재 순서: `documents` 행을 먼저 만들고(`index_status` 대기) 받은 `doc_id`로 청크 ID를 만든 뒤, 색인이 끝나면 상태를 완료·실패로 바꾼다. 실패해도 행은 남겨 A-02에서 재색인한다.

데이터 형식은 [데이터 모델](./data-model.md)을 따른다.

## 2. 권한 규칙 (S-03)

이 서비스의 핵심은 "권한 없는 문서는 검색·답변·보고서·원문 어디에도 나오지 않는 것"이다.

### 2.1 열람 매트릭스

| 역할 \ 문서 | 전사 public | 자사 internal | 타사 internal (공유 OFF) | 타사 internal (공유 ON) | 자사 confidential | 타사 confidential |
| --- | :-: | :-: | :-: | :-: | :-: | :-: |
| 일반 사원 `employee` | ✅ | ✅ | 승인 시 ✅ | ✅ | 승인 시 ✅ | 승인 시 ✅ |
| 계열사 관리자 `company_admin` | ✅ | ✅ | 승인 시 ✅ | ✅ | ✅ | 승인 시 ✅ |
| 최종 어드민 `super_admin` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

- 타사 문서를 보는 방법은 ① 그룹사 공유 ON ② 권한 승인(A-05) 두 가지뿐이다.
- 그룹사 공유는 `internal` 문서만 가능하고, 관리자 페이지에서만 바꾼다. 기본 OFF.
- `confidential`은 공유할 수 없다 (계약 단가 등). 승인으로만 연다.

### 2.2 관리 권한

| 행위 | 일반 사원 | 계열사 관리자 | 최종 어드민 |
| --- | :-: | --- | --- |
| 검색·질의응답·보고서·내 정보·내 히스토리 | ✅ | ✅ | ✅ |
| 열람 권한 요청 | ✅ | ✅ | - |
| 문서 업로드·삭제·재색인 | ❌ | 자사 문서만 | 전체 |
| 그룹사 공유 ON/OFF | ❌ | 자사 internal만 | 전체 internal |
| 권한 요청 승인·반려 | ❌ | 자사 소유 문서만 | 전체 |
| 감사 로그 조회 | ❌ | 자사 직원 로그만 | 전체 |
| DART 수집·계열사 추가·전체 재색인 | ❌ | ❌ | ✅ |

### 2.3 구현 원칙

1. 권한 조건은 `permissions` 패키지의 권한 필터 함수 **한 곳에서만** 만든다. 검색·질의응답·보고서 수집·원문 보기가 모두 이 함수를 거친다.
2. **사전 필터만 허용**한다. Chroma `where` 조건에 넣어 벡터 검색 전에 거른다. 결과를 받은 뒤 거르는 코드는 만들지 않는다.
3. BM25(S-06)는 권한 필터를 통과한 청크만으로 인덱스를 만든다.
4. 원문 보기·다운로드·보고서 다시 열기는 문서 접근 확인 함수로 **다시** 확인한다 (권한이 그 사이 바뀌었을 수 있다).
5. 공유 ON/OFF(A-03)는 MySQL `documents`와 Chroma의 해당 문서 청크 메타데이터를 함께 바꾼다. 하나라도 실패하면 둘 다 되돌린다.
6. 권한이 없는 타사 문서는 검색 결과에 **제목만** 보여 주고 "내 권한 요청"(M-03)을 띄운다. 본문·청크는 LLM에 넣지 않는다.

### 2.4 Chroma where 예시

현대무벡스 일반 사원, 승인 문서 1건:

```python
where = {
    "$or": [
        {"access_level": "public"},
        {"$and": [{"company_id": "MVX"}, {"access_level": "internal"}]},
        {"$and": [{"access_level": "internal"}, {"is_group_shared": True}]},
        {"doc_id": {"$in": ["3f9c0a…"]}},  # 승인 문서 (없으면 이 줄을 뺀다)
    ]
}
# S-02 필터는 바깥에 $and로 붙인다
final_where = {"$and": [where, {"company_id": {"$in": ["MVX", "ELV"]}}, {"published_date": {"$gte": 20250101}}]}
```

## 3. 패키지 사이 약속

다른 묶음이 만든 기능은 아래 지점으로만 쓴다. 정확한 이름·입력·출력은 메소드 명세서를 따른다.

| 쓰는 쪽 | 부르는 것 | 만드는 쪽 |
| --- | --- | --- |
| 모든 화면 | 현재 로그인 사용자 조회 (`auth/session.py`) | 검색·계정 |
| 검색·답변·보고서 | 권한 필터 생성, 문서 접근 확인 (`permissions/services`) | 검색·계정 |
| 답변·보고서 | 통합 검색 (`search/services`) | 검색·계정 |
| 관리자 업로드·DART | 적재 파이프라인 (`ingestion/pipeline.py`) | 문서·관리자 |
| 모든 서비스 | 감사 로그 기록 (`admin/services/audit_service.py`) | 문서·관리자 |
| 답변 출처·보고서 각주 | 출처 배지·원문 뷰어 (`documents/views/components`) | 답변·보고서 |

이 지점의 시그니처를 바꾸면 쓰는 쪽 담당에게 먼저 알리고 PR에 표시한다.
