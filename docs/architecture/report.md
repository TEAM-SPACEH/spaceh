# 보고서 작성 기준 (R-01~R-04)

> 회사·기간을 고르면 이미 구현된 검색·권한·답변 기능으로 근거를 모으고, 그 근거만으로 섹션을 쓰는 보고서다. 새 데이터 수집이나 수치 계산은 하지 않는다. 메소드 이름·입출력은 「보고서 메소드 명세서」를 따르고, 이 문서는 내용·분량·검증 기준만 정한다. 권한 규칙은 [구조 개요](./overview.md) §2를 따른다.

## 1. 흐름

| 단계 | 쓰는 기능 | 비고 |
| --- | --- | --- |
| 1. 조건 입력 | `render_report_form()` | 양식(종합 / 분기 실적) · 주제 · 회사 · 기간 |
| 2. 필터 변환 | `apply_metadata_filters()` (S-02) | 회사는 `company_id`, 기간은 `published_date`(YYYYMMDD) |
| 3. 근거 수집 (R-01) | `hybrid_search(주제, 필터, user, audit=False)` (S-06) | 회사마다 한 번씩 호출한다. S-03 권한 필터는 함수 안에서 검색 전에 적용된다 |
| 4. 섹션 작성 (R-02) | `generate_draft()` → `generate_section()` | 양식의 섹션 순서대로 섹션마다 LLM을 한 번 부른다 |
| 5. 출처·원문 (R-03) | `prepare_context()` 출처 모양, 출처 패널, 원문 뷰어 (S-04·S-05) | 같은 출처 모양을 쓰므로 화면 컴포넌트를 그대로 재사용한다 |
| 6. 감사 로그 | `record_audit_log(..., "report_create", ...)` | 3단계 검색마다 `search`를 남기지 않고 보고서 생성 1건만 남긴다 |

- 회사 이름은 `company_service.get_company_options()`에서 코드로 찾는다. 회사를 이름으로 고정하지 않는다 (A-07).
- 같은 주제라도 보는 사람의 권한에 따라 근거가 달라지므로 보고서도 사용자마다 다르다.

## 2. 상세보고서 섹션별 내용·분량

[상세보고서] 탭(`render_report()`)은 R-02 섹션을 보여 준다. 모든 문장은 근거 번호 `[n]`으로 끝나고, 수치는 근거에 적힌 그대로 옮기며 계산·반올림하지 않는다.

| 섹션 | 양식 | 내용 | 분량 |
| --- | --- | --- | --- |
| 개요 | 종합·분기 실적 | 주제 배경·의미(LLM) + 범위 문장(코드 작성: 회사 수·기간·근거 문서 수) | 200~300자 |
| 현황 | 종합 | 회사별 문단. 주제 관련 사업 내용·주요 사실·원문 수치 | 회사당 200~350자 |
| 시너지 | 종합 | 공통 주제·협업 가능성 2~3개. 항목마다 서로 다른 회사의 근거를 2개 이상 인용 | 300~450자 |
| 실적 비교 | 분기 실적 | 회사별 매출·영업이익 등 근거 수치 그대로 + 기준 기간 | 회사당 150~250자 |
| 제언 | 종합·분기 실적 | 실행 가능한 제언 3개 이내. 각 제언 끝에 근거가 된 `[n]` | 250~400자 |

- 전체 분량은 회사 3곳 기준 약 1,500~2,300자(A4 2~3쪽)다.
- 문서 1개를 깊게 분석하는 재무 보고서(재무제표 전체 행·비율 계산)는 만들지 않는다 ([결정 기록](../decisions.md) 10/29).

## 3. 근거 수집 기준 (R-01)

- 회사 필터를 하나씩 걸어 회사마다 따로 검색한다. 한 번에 검색하면 근거가 많은 회사가 근거 글자 예산(`EVIDENCE_CHAR_BUDGET`, 1만 2천 자)을 채워 뒤쪽 회사가 빠진다.
- 섹션에 넘기는 청크는 회사를 번갈아(A1 → B1 → C1 → A2 …) 담고, 섹션당 최대 12개로 제한한다. 번호가 커질수록 범위 밖 번호 오류가 늘어난다.
- 결과가 0건인 회사는 `CollectionResult.empty_companies`에 회사 코드로 넣는다.

## 4. LLM 결과가 검증에 잘리지 않게 하는 기준 (R-02)

### 4.1 LLM에게 시키지 않는 문장

근거가 없는 문장은 근거 번호 검사(`has_valid_citations`)를 통과할 수 없으므로 코드가 쓰고 검사에서 뺀다.

- 개요의 범위 문장: "본 보고서는 {회사 이름들} {회사 수}개 회사의 {시작일}~{종료일} 문서 {근거 문서 수}건을 근거로 작성함." 근거 문서 수는 서로 다른 `doc_id` 수다.
- 근거가 0건인 회사: 현황(분기 실적은 실적 비교) 끝에 "{회사 이름}: 해당 주제의 근거 자료 없음"을 붙인다.
- 프롬프트 공통 규칙에 "근거가 없는 회사, 대상 회사·기간은 쓰지 않는다(시스템이 표시)"를 넣는다.

### 4.2 근거 번호 검사에 실패했을 때

섹션 전체를 바로 버리지 않고 아래 순서로 처리한다.

1. 실패 이유(예: "3번째 문장에 근거 번호 없음", "[14]는 근거 범위 밖")를 프롬프트에 붙여 한 번만 다시 요청한다.
2. 다시 실패하면 잘못된 문장만 뺀다. 남은 문장이 원래의 60% 이상이면서 2문장 이상이면 섹션을 살리고 `Section.partial = True`로 표시한다. 화면은 이 섹션에 유의사항을 보여 준다.
3. 그보다 적게 남으면 섹션 본문을 "근거 자료 없음"으로 바꾼다.

### 4.3 출력 끊김

- 섹션 호출의 `max_tokens`는 1,200으로 둔다 (한국어 약 1,500~2,000자, 분량 상한보다 넉넉함).
- 응답의 `finish_reason`이 `length`이면 마지막 문장이 끊긴 것이므로 실패로 보고 4.2의 1단계로 보낸다.
- 분량이 지침을 넘어도 코드로 자르지 않는다. 문장 중간을 자르면 근거 번호가 깨진다. 분량은 프롬프트 지침으로만 맞춘다.

### 4.4 수치 확인

본문의 숫자(%, 억 원 등)가 그 문장이 인용한 근거 청크 글자에 실제로 있는지 확인한다. 없으면 4.2의 "잘못된 문장"으로 처리한다.

## 5. 각주 번호 (R-03)

- `[n]`은 섹션마다 1부터 시작한다. 상세보고서로 이어 붙이고 각주를 만들 때 보고서 전체 번호로 다시 매긴다. 같은 청크는 같은 번호를 쓰고 본문의 `[n]`도 함께 바꾼다.
- 각주는 `[번호] 회사명 · 파일명 · 위치` 형식이다(`render_footnotes()`). 원문 인용을 붙이면 마스킹된 청크 본문에서 150자 정도로 자른다. 원본 파일을 다시 읽지 않는다.

## 6. "근거 자료 없음"이 정상인 경우

- 분기 실적: 고른 기간의 문서에 수치가 글로 적혀 있어야 나온다.
- 시너지: 두 회사 이상에서 같은 주제의 근거가 나와야 쓸 수 있다.
- 권한: 사용자가 볼 수 없는 문서는 근거에서 빠지므로 회사·섹션이 비어 보일 수 있다.

## 7. 화면 (보고서 메소드 명세서)

| 메소드 | 내용 |
| --- | --- |
| `render_report_page()` | 로그인 확인 후 조건 입력 → 결과 탭 |
| `render_report_form()` | 양식·주제·회사·기간 입력, `ReportRequest` 반환 |
| `render_result_tabs()` | [1페이지 요약] / [상세보고서] 두 탭, 처음에는 요약 탭 |
| `render_exec_summary()` | 핵심 내용 · 계열사별 시사점 · 권고안, 항목마다 [상세 보기] |
| `go_to_detail()` | [상세 보기]의 섹션으로 [상세보고서] 탭 이동 |
| `render_report()` | 상세보고서 섹션 제목·본문, 섹션 앵커 |
| `render_footnotes()` | 본문 아래 각주 목록, 내부 문서는 원문 뷰어로 연결 |

- 1페이지 요약(R-04)도 R-02와 같은 규칙(근거 밖 금지, 문장마다 `[n]`, 계산 없음)을 따르고 R-02 출처 번호를 이어 쓴다.
