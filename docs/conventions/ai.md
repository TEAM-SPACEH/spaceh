# AI 활용 규칙

AI 도구(ChatGPT, Claude, Copilot, Cursor, Codex 등)로 코드를 쓰는 것은 자유다. 결과에 대한 책임은 커밋한 사람에게 있다.

## 1. 원칙

1. 설명할 수 없는 코드는 커밋하지 않는다. 리뷰에서 "이 줄은 왜 있어요?"에 답할 수 있어야 한다.
2. 실행해 본 코드만 PR로 보낸다.
3. 명세가 AI보다 우선이다. 메소드 이름·입력·출력은 메소드 명세서대로 쓴다.

## 2. AI에게 줄 것

- 기능명세표의 해당 기능 행 (기능 ID, 상세 설명)
- 메소드 명세서의 해당 메소드 행 (모듈, 메소드명, 입력·출력)
- [코드 규칙](./coding.md)
- 호출할 기존 코드 (서비스 함수, 공통 모델)

Claude Code·Codex·Gemini CLI는 저장소의 `AGENTS.md`를 자동으로 읽는다. 웹 채팅 AI에는 위 내용을 직접 붙여 넣는다.

## 3. AI에게 주면 안 되는 것

- `.env` 내용, OpenAI·DART API 키, DB·시드 계정 비밀번호
- 팀원의 실제 개인정보
- 출처가 공개되지 않은 실제 기업 내부 자료 (공개 자료 + 직접 만든 목데이터만 쓴다)

## 4. 결과 확인

- [ ] `requirements.txt`에 없는 패키지를 쓰지 않았는가
- [ ] SQL에 `%s` 바인딩을 썼는가, 화면에서 DB를 직접 부르지 않는가
- [ ] 권한 확인(S-03)이 빠지지 않았는가
- [ ] 필요 없는 파일을 만들거나 다른 사람 파일을 고치지 않았는가
- [ ] 실제로 실행하고 테스트했는가

## 5. PR에 적기

AI로 만든 비중이 큰 PR은 Implementation Notes에 "AI 활용: 어떤 부분을, 어떻게 검증했는지"를 한 줄로 적는다.

## 6. 서비스 안의 OpenAI API

- 키는 `.env`의 `OPENAI_API_KEY`로만 쓴다. 메신저로 키를 보내지 않는다.
- 개발은 `gpt-4o-mini`, 시연에서만 `gpt-4o`.
- 반복문 안에서 LLM을 부르거나 같은 문서를 매번 다시 임베딩하지 않는다.
- 프롬프트를 바꾸면 평가 질문셋으로 전후를 비교하고 결과를 PR에 적는다.

## 7. CodeRabbit 리뷰

설정은 저장소 루트 `.coderabbit.yaml`. `develop`으로 가는 PR마다 한국어로 리뷰를 단다 (draft 제외).

- 사람 리뷰를 대신하지 않는다. 승인은 짝꿍·팀장이 한다.
- 제안을 그대로 커밋하지 않는다. 위 §4 체크리스트로 확인하고, 이해한 것만 반영한다.
- 우리 규칙(수업 범위, 사전 필터, `%s` 바인딩)과 다른 제안은 답글로 이유를 남기고 resolve 한다.
- PR 코멘트에 `@coderabbitai`를 붙여 질문할 수 있다. 다시 리뷰받으려면 `@coderabbitai review`.
